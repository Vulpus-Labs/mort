## Summary

Create MIDI items, insert, replace and read notes and CC, with positions
and lengths in musical units.

## Acceptance criteria

- [x] `midi.write` into a new or existing item over a range: notes
      (pitch, start, length, velocity, channel) and CC. Mode `add` or
      `replace-range`.
- [x] `midi.read` returns notes and CC over a range.
- [x] CLI accepts a compact note list (`C3:9.1:1b:100 E3:+1b:1b`) and a
      file (`.mid` or the same text format).
- [x] Tests over the fake. Smoke: the notes play in REAPER at the right
      positions across a tempo change.

## Close-out (2026-11-19)

- Bridge:
  - `Live` creates MIDI items (`CreateNewMIDIItemInProj`), reads and
    writes notes and CCs through the take's ticks
    (`MIDI_GetPPQPosFromProjTime` and back), and deletes by range, highest
    index first.
  - After every change it marks the item dirty (`MarkTrackItemsDirty`).
    Without that, REAPER's undo block records nothing.
- RPCs:
  - `midi.read`: MIDI items on a track, with notes and CCs, optionally
    by range.
  - `midi.write`: notes and CCs into a MIDI item that already covers the
    events and range, or a new one. Mode `add` or `replace`; `replace`
    clears notes starting, and CCs falling, in the range.
  - Every edit result now carries `undo_point` (ADR 0004 §8).
- CLI:
  - `mort midi <track> [RANGE] [EVENTS…] [--replace] [--file PATH]`.
  - Notes are `PITCH:START[:LENGTH[:VELOCITY[:CHANNEL]]]`, with C4 = 60
    and sharps and flats allowed. Lengths are `1b` or `0.5s`. `+1b` counts
    from the previous event's start, so `+0b` stacks a chord.
  - CCs are `ccN[@CH]:START=VALUE`.
  - Files: a `.mid` file (format 0 or 1, read by `smf.rs`, placed at the
    range's start, with the project's tempo map deciding the times), or
    a text file of the same tokens with `#` comments.
  - A first argument without `..` is taken as an event, not a range.
  - Listing shows bar.beat spans, pitch names, velocity and channel.
- Smoke, 45 checks, all `ok` in REAPER 7.67. The smoke project now
  changes from 120 to 90 bpm at bar 9.
  - Time conversion across the change.
  - A note from 8.4 lasting two beats lands at 15.5 s to 16.667 s, the
    same as mort's own calculation.
  - Writing into an existing item, replace, refusing a note that ends
    before it starts, and undo.
  - Every edit in the run reports `undo_point: true`.
- Found by the smoke run: MIDI edits left no undo point, so `undo`
  reverted an earlier automation edit. Fixed with `MarkTrackItemsDirty`,
  and guarded by `undo_point` from now on.
- Tests: CLI 23 (3 for MIDI: tokens, replace, undo, files, tempo change),
  plus unit tests for pitches, tokens and the SMF reader.
